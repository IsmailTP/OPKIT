Wireshark / TShark

The world's foremost network protocol analyser. Captures and interactively browses traffic on a computer network. TShark is the CLI equivalent — powerful for scripting, remote capture, and field extraction.

Live Capture PCAP Analysis Display Filters BPF Filters TShark CLI Credential Extraction
First 3 Commands — Quick Start
Capture → Filter → Extract. Do this before anything else.
# tshark -i eth0 -w capture.pcap capture live
$ tshark -r capture.pcap -Y "http.request" filter requests
$ tshark -r capture.pcap -Y "http.request" -T fields -e ip.src -e http.host -e http.request.uri extract fields
Interface tip: -i any is Linux-only. Use tshark -D to list available interface IDs/names on macOS and Windows.
Display Filter vs. Capture Filter — Never Mix These.

-Y = display filter (Wireshark syntax — applied after capture or during file reading).

-f = capture filter (BPF syntax — applied kernel-level during live capture).

These are different languages. You cannot mix them.

Permanent traffic loss: Capture filters permanently discard traffic at the NIC level. If you capture with -f "port 80", you will never see port 8080 or TLS traffic in that pcap file.

Before you ask "why is my capture empty?"
  • Switched networks: You only see traffic to/from your own NIC unless there's a mirror port or tap. Promiscuous mode helps on hubs and Wi-Fi monitors — not modern switches.
  • Permission errors: Raw socket capture requires elevated privileges. Run as sudo, or grant Linux capability so you don't need sudo — see the dumpcap block below.
  • PCAPs contain secrets: Raw captures record unencrypted credentials, session cookies, and PII. Treat captures as sensitive evidence — encrypt at rest, never email raw pcaps.

Display Filters

Protocol rename deprecation note: The old ssl.* filters were renamed to tls.* in Wireshark 3.0+. If you copy a filter from an older writeup and it says ssl.handshake, rewrite it as tls.handshake.

Credential Extraction

These filters surface cleartext credentials in unencrypted protocols. Base64 values in HTTP Basic auth decode with echo '<value>' | base64 -d.
HTTP Basic auth headers
Extract Authorization headers with TShark. Note that the value is Base64 — decode with base64 -d.
$ tshark -r capture.pcap -Y "http.authorization" -T fields -e ip.src -e http.host -e http.authorization
$ tshark -r capture.pcap -Y "http.authorization" -T fields -e http.authorization | awk '{print $2}' | base64 -d auto-decode base64
HTTP POST bodies
Extract form submissions (http.file_data) — where login credentials live in most web apps.
$ tshark -r capture.pcap -Y "http.request.method == \"POST\"" -T fields -e ip.src -e http.host -e http.file_data
$ tshark -r capture.pcap -Y "http.request.method == \"POST\" and (http.file_data contains \"user\" or http.file_data contains \"pass\")" -T fields -e http.file_data filter login forms
FTP / POP3 / IMAP credentials
Extract USER and PASS commands from cleartext protocols.
$ tshark -r capture.pcap -Y "ftp.request.command in {\"USER\",\"PASS\"}" -T fields -e ip.src -e ftp.request.command -e ftp.request.arg
$ tshark -r capture.pcap -Y "pop.request.command in {\"USER\",\"PASS\"} or imap.request.command in {\"LOGIN\"}" -T fields -e ip.src -e frame.protocols -e data.data
Kerberos usernames
Extract CNameString from AS-REQ packets — useful for AD username enumeration before password spraying.
$ tshark -r capture.pcap -Y "kerberos.CNameString and kerberos.msg_type == 10" -T fields -e ip.src -e kerberos.CNameString AS-REQ usernames

Capture Filters (BPF)

Capture filters run inside the capture engine (BPF syntax). Once traffic is filtered out at capture time, it is gone — you cannot recover it later by changing the display filter.

TShark Field Extraction

Extract specific fields
Print only selected fields from packets
$tshark -r capture.pcap -T fields -e ip.src -e ip.dst -e tcp.dstport
$tshark -r capture.pcap -Y "http.request" -T fields -e http.host -e http.request.uri
Follow TCP stream
Reconstruct a TCP conversation
$tshark -r capture.pcap -q -z follow,tcp,ascii,0
Extract and pipe to CSV
Combine -T fields, column headers, and comma delimiters with shell redirection for triage and report generation.
$tshark -r capture.pcap -T fields -E header=y -E separator=, -E quote=d -e frame.number -e ip.src -e ip.dst -e _ws.col.Protocol -e _ws.col.Info > report.csv
$tshark -r capture.pcap -Y "http.request" -T fields -E header=y -E separator=, -e ip.src -e http.host -e http.request.uri > http_requests.csv

Statistics & Analysis

Use TShark's -q -z engine to compute summary statistics, extract session conversations, reconstruct hierarchies, or pull exported artifacts straight into reporting directories without opening the GUI.
CommandWhat it does
tshark -r capture.pcap -q -z io,stat,1Per-second packet and byte throughput (traffic volume over time)
tshark -r capture.pcap -q -z endpoints,ipIP endpoints with byte counts (who talked to whom, and how much)
tshark -r capture.pcap -q -z conv,tcpTCP conversations (every src ↔ dst pair with duration & throughput)
tshark -r capture.pcap -q -z http,treeHTTP request/response tree (URL hierarchy and status code distribution)
tshark -r capture.pcap -q -z dns,treeDNS query tree (all domains queried — spot C2 beacons / data exfil)
tshark -r capture.pcap -q -z expertExpert info (all dissector warnings, errors, and protocol anomalies)
tshark -r capture.pcap --export-objects http,./out/Export HTTP objects (pull out all files transferred over HTTP)
