Web Fuzzer · Go

ffuf

Fuzz Faster U Fool — a blazing-fast web fuzzer written in Go. Designed for directory discovery, parameter fuzzing, virtual host enumeration, and any HTTP-based wordlist attack. Supports multiple keywords (FUZZ, W1, W2…) simultaneously.

First 3 Commands — Quick Start
Three commands cover 80% of ffuf usage.
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -u https://target/FUZZ -ac calibrated directory scan
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -u https://target/FUZZ -ac -e .php,.bak,.zip with extensions + backups
$ ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -u https://target -H "Host: FUZZ.target" -ac vhost discovery
Why am I seeing 400 results? — The filter traps.
  • -mc all is a trap: It disables filtering entirely. On any modern app (WordPress, Django, Express) you'll drown in 404s and 3xx redirects that all lead to the same catch-all page.
  • -fs is a guess, not a rule: If your guessed byte length is off by one, you either filter all real findings or filter nothing. Use -ac when you don't know the baseline.
  • -t 40 is aggressive: Default threads overwhelm small apps, trigger WAFs, and can lock accounts on login endpoints. Drop to -t 10 on unknown targets, or use -rate 20 to cap requests per second.
  • Cluster bomb explodes: -mode clusterbomb (the default for multiple -w) multiplies list lengths. Two lists of 100 = 10,000 requests; three lists of 100 = 1,000,000. Always estimate len(A) × len(B) × … before launching against live targets.
Wordlist choice matters more than flags.

dirb/common.txt is a 2003 relic with ~4,600 entries. SecLists raft-medium-directories.txt has ~30,000 entries and finds 3–5× more paths on modern apps.

Recommended wordlist paths to reference in examples:

  • Directories: /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt
  • Files: /usr/share/seclists/Discovery/Web-Content/raft-medium-files.txt
  • Vhosts: /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
  • Parameters: /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt

Directory Fuzzing

Calibrated directory scan (recommended default)
-ac sends a baseline request, learns the default response size, and hides anything matching it. Right answer for 90% of targets.
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -u https://target/FUZZ -ac
Directory scan with extensions and backup files
The -e extensions hunt for developer leftovers — .bak, .old, .swp (vim), archive, and database dump files. -mc 200 restricts output to successful hits only. This single pattern finds source code, config files, and DB exports more often than any other ffuf technique.
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -u https://target/FUZZ -ac -e .php,.bak,.old,.backup,.swp,.zip,.tar.gz,.sql -mc 200
Recursive directory scan
Automatically go deeper into discovered directories up to the specified depth.
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -u https://target/FUZZ -recursion -recursion-depth 3 -ac

Parameter Fuzzing

Fuzz an authenticated request saved from Burp
Export any request from Burp (Ctrl+Shift+S in Repeater, or right-click → "Save item" in Proxy), open the saved file, and replace the value you want to fuzz with the literal word FUZZ. ffuf preserves cookies, CSRF tokens, JSON bodies, and custom headers that are painful to re-enter as flags. This is how professionals fuzz authenticated endpoints.
$ ffuf -request request.txt -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt -ac
GET parameter fuzzing
Find hidden or unlinked query parameters on an endpoint.
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt -u "https://target/page?FUZZ=value" -ac
POST body fuzzing
Fuzz form fields or JSON attributes inside POST request bodies.
$ ffuf -w wordlist.txt -u https://target/login -X POST -d "user=FUZZ&pass=password" -H "Content-Type: application/x-www-form-urlencoded" -ac
Cluster bomb — for every combination
Fuzz two positions simultaneously testing every possible combination.
⚠️ Cluster bomb multiplies list lengths: len(A) × len(B) × …. Two lists of 100 produce 10,000 requests; three lists of 100 produce 1,000,000. Always estimate before launching against a live target.
$ ffuf -w users.txt:W1 -w passwords.txt:W2 -u https://target/login -d "user=W1&pass=W2" -mode clusterbomb
Pitchfork — for paired lists
Pitchfork pairs word N from list A with word N from list B — 100 lines × 100 lines = 100 iterations, not 10,000. Right choice when lists are naturally paired: leaked username-to-password dumps, credential stuff lists, or test-case matrices. -mode clusterbomb is the wrong mode for these.
$ ffuf -w users.txt:W1 -w passwords.txt:W2 -u https://target/login -X POST -d "user=W1&pass=W2" -H "Content-Type: application/x-www-form-urlencoded" -mode pitchfork -ac

Virtual Host Scanning

How to pick -fs: A vhost scan only works if you know the default response size for a nonexistent host. First, request a guaranteed-invalid host and measure the response:
curl -s -H "Host: nonexistent.example.com" https://target | wc -c
The output is your -fs value. Or add -ac and skip this step entirely — ffuf will do the calibration automatically.
Manual calibration workflow (measured -fs)
Measure the default catch-all vhost byte size with curl, then filter out all matching responses.
$ curl -s -H "Host: nonexistent.example.com" https://target | wc -c
$ ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -u https://target -H "Host: FUZZ.target" -fs <measured-size> replace with curl output
Auto-calibrated vhost discovery (-ac)
Automatically calibrate against the target's default catch-all vhost response without manual byte measurement.
$ ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -u https://target -H "Host: FUZZ.target" -ac

Response Filtering

Use -ac before guessing: If you don't know the baseline response size, -ac measures it and filters automatically. Only reach for -fs / -fw / -fl when you need to filter on something -ac can't detect (a very specific response, or after inspecting a known pattern).

Quick Cheatsheet

Basic dir fuzz
ffuf -w list.txt -u https://target/FUZZ -ac
With extensions
ffuf -w list.txt -u https://target/FUZZ -ac -e .php,.bak,.zip
Filter 404s
ffuf -w list.txt -u https://target/FUZZ -fc 404
VHost scan
ffuf -w subs.txt -u https://target -H "Host: FUZZ.target" -ac
Save JSON output
ffuf -w list.txt -u https://target/FUZZ -o results.json -of json
Recursive
ffuf -w list.txt -u https://target/FUZZ -recursion -recursion-depth 2 -ac
Replay through BurpCHAIN
ffuf -w list.txt -u https://target/FUZZ -x http://127.0.0.1:8080 -ac
HTML reportCHAIN
ffuf -w list.txt -u https://target/FUZZ -o results.html -of html -ac
Feed to SQLmapCHAIN
