Offline Password Security Auditing & Hash Recovery

John the Ripper

A versatile offline password security auditor supporting 400+ cipher and hash formats. Master rule-based dictionary mangling, single-crack username mutations, multi-core CPU fork parallelization, and the essential 2john extraction pipeline for SSH keys, archives, and system shadow files.

Rule Mangling (--rules) Single Crack Mode 2john Extractors Format Explicit (--format) Multi-Core (--fork) Linux /etc/shadow Windows NTLM GPU vs Hashcat
First 3 Commands — Quick Start
Rules, extraction, and explicit formats — the three things most tutorials skip.
$ john --wordlist=rockyou.txt --rules hashes.txt Dictionary attack with mangling rules
$ ssh2john id_rsa > hash.txt && john hash.txt Extract & crack SSH key passphrase
$ john --format=NT --wordlist=rockyou.txt ntlm.txt Crack Windows NTLM hashes (explicit format)

Critical Pitfalls & Warnings

Why is John finding zero passwords? — The format, rules, and show traps.
  • --rules is not optional: Without rules, John tries only the literal words in your wordlist and misses the vast majority of human passwords (capitalization, appended digits, leetspeak). Always add --rules on the first dictionary pass. The best64 ruleset alone is a fast, low-cost multiplier.
  • Auto-detection fails silently: John can misidentify a 32-hex-character hash (MD5, NTLM, and LM all look similar). It will run "successfully" and crack nothing because it is solving the wrong cryptographic algorithm. Always specify --format= when you know the hash type. If John finishes in seconds with 0 cracked, the format is likely wrong.
  • --show requires the same format flag: If you cracked hashes with --format=NT and then run john --show hashes.txt without that flag, John will report nothing because it looks in the potfile for default-detected formats. Always use the exact same --format= with --show that you used during the crack.
  • John is CPU-first: It is excellent for quick checks, single-crack username mangling, and messy real-world files, but GPU-based tools like Hashcat are 50–100× faster on raw hashes. If you have a dedicated GPU, use Hashcat for large-scale cracking and John for extraction and quick inspection.

Setup & Hash Identification

Before cracking, you must accurately determine the algorithm and verify that your John environment supports the targeted cipher.

Identify an unknown hash
Inspect hash length, character set, and salt delimiters to find algorithm candidates
$ hashid -m -j '098f6bcd4621d373cade4e832627b4f6'
$ hash-identifier
Identification Tip: hashid -m -j outputs both the Hashcat mode (-m) and the John the Ripper format flag (-j), allowing you to immediately select the correct format string.
List and filter supported formats
Search John's internal database for the exact --format= identifier string
$ john --list=formats | grep -i ntlm
$ john --list=formats | grep -i sha512
$ john --list=subformats
Verify John the Ripper version & Jumbo build
Confirm whether you are running Jumbo (with 2john tools) or restricted core John
$ john --version
Jumbo Build Note: Kali Linux and Parrot OS ship with the community-enhanced John Jumbo package by default. If running upstream core John, 2john extractors and modern OpenCL formats will not be present.

Attack Modes

Single crack mode (username & GECOS mangling)
Uses login names, full names, and home directory tokens to synthesize guesses
$ john --single hashes.txt
$ john --single --format=sha512crypt combined.txt
Why Single Mode First: Single mode is John's unique superpower. It parses username and GECOS information in user:hash lines and applies mutations (e.g. jdoe → Jdoe1!, jdoe2024). It executes in seconds and catches weak passwords that general wordlists miss completely.
Wordlist mode with mangling rules (the primary attack)
Combine dictionary words with capitalization, appending digits, and leetspeak rules
$ john --wordlist=/usr/share/wordlists/rockyou.txt --rules hashes.txt
$ john --wordlist=rockyou.txt --rules=best64 hashes.txt
$ john --wordlist=rockyou.txt --rules=Jumbo hashes.txt
Rule Sets: Bare --rules triggers the default [List.Rules:Wordlist] ruleset in john.conf. Use --rules=best64 for a lightning-fast multiplier, or --rules=Jumbo for deep, extensive password mutations.
Incremental (smart brute-force) mode
Frequency-guided character generation across length and character subsets
$ john --incremental hashes.txt
$ john --incremental=Digits hashes.txt
$ john --incremental=Alnum hashes.txt
Char-Frequency Guidance: John does not brute-force randomly (AAA, AAB...). It uses trigram probability tables trained on real passwords. Restricting to Digits or Alnum limits the keyspace when targeting numeric PINs or restricted passwords.
Inspect results & manage cracking sessions
Display recovered plaintexts, check live status, or resume interrupted jobs
$ john --show hashes.txt
$ john --show --format=NT ntlm.txt
$ john --status
$ john --restore
$ john --session=audit24 --wordlist=rockyou.txt hashes.txt
$ john --restore=audit24

Hash Formats & Auto-Detection

Auto-detection can confuse raw hashes. A 32-character hex string could be MD5, NTLM, or LM. If John finds zero passwords quickly, the format is likely wrong. Use hashid to identify the hash first, then force the correct format with --format=.

2john Extraction Utilities & Workflows

The 2john family: extracting hashes from protected files. John cannot directly read encrypted ZIPs, SSH keys, or Office documents. The 2john helper scripts convert these files into a crackable hash format. The workflow is always: extract → crack → show. For example: zip2john secret.zip > hash.txt, then john hash.txt, then john --show hash.txt. This three-step pattern applies to every 2john utility.
SSH private key passphrase workflow
Extract the cipher blob from encrypted RSA/DSA/Ed25519 keys and crack the passphrase
$ ssh2john id_rsa > ssh_hash.txt
$ john --wordlist=/usr/share/wordlists/rockyou.txt ssh_hash.txt
$ john --show ssh_hash.txt
Password-protected ZIP, Office, KeePass, & PDF files
Extract hashes from documents and archives using dedicated python/C extractors
$ zip2john secret.zip > zip_hash.txt && john --wordlist=rockyou.txt zip_hash.txt
$ office2john sheet.xlsx > office_hash.txt && john --wordlist=rockyou.txt office_hash.txt
$ keepass2john database.kdbx > kp_hash.txt && john --wordlist=rockyou.txt kp_hash.txt
$ pdf2john confidential.pdf > pdf_hash.txt && john --wordlist=rockyou.txt pdf_hash.txt
$ rar2john archive.rar > rar_hash.txt && john --wordlist=rockyou.txt rar_hash.txt
Linux /etc/shadow & /etc/passwd unshadow workflow
Combine system user account entries with password hashes into John format
$ unshadow /etc/passwd /etc/shadow > combined.txt
$ john --format=sha512crypt --wordlist=rockyou.txt --rules combined.txt
$ john --show --format=sha512crypt combined.txt

Rules & Wordlist Mangling

The core --rules flag (Wordlist default)
Applies in-memory password mutations without pre-generating giant files on disk
$ john --wordlist=rockyou.txt --rules hashes.txt
How Rules Work: Real humans rarely pick dictionary words as-is. They capitalize the first letter, append birth years, or substitute characters (password → Password2024!). John's rule engine generates these candidate mutations on the fly in CPU RAM.
Named rulesets (best64, Jumbo, KoreLogic)
Select specialized rule collections calibrated for speed, coverage, or enterprise patterns
$ john --wordlist=rockyou.txt --rules=best64 hashes.txt
$ john --wordlist=rockyou.txt --rules=Jumbo hashes.txt
$ john --wordlist=rockyou.txt --rules=KoreLogic hashes.txt
When to Use: best64 is the gold standard for initial fast passes (64 highest-yield transformations). Jumbo executes exhaustive permutations when CPU time permits. KoreLogic applies aggressive enterprise security assessment mutations.
Define custom rules in john.conf
Craft custom mutation logic to target specific organization password policies
# Append to /etc/john/john.conf or ~/.john/john.conf
[List.Rules:CompanyPolicy]
c Az"[0-9][0-9]"         # Capitalize 1st letter, append 2 digits
c Az"[0-9][0-9][!@#$]"   # Capitalize, append 2 digits + special symbol
$ john --wordlist=rockyou.txt --rules=CompanyPolicy hashes.txt
Multi-core parallelization (--fork)
Spawn isolated worker processes across CPU cores (John Jumbo feature)
$ john --fork=4 --wordlist=rockyou.txt --rules=best64 hashes.txt
$ john --fork=8 --single combined.txt
Fork vs Threading: John Jumbo uses POSIX fork() to create separate process instances that communicate through IPC and automatically share cracked plaintexts in ~/.john/john.pot. Match --fork to your physical CPU core count (nproc).

GPU Acceleration & Hashcat Integration

John the Ripper is CPU-first; Hashcat is GPU-first. Understanding the division of labor between both tools is crucial for scaling your cracking workflow.

CriteriaJohn the Ripper (Jumbo)Hashcat
Primary ArchitectureCPU-first (multi-process core scaling)GPU-first (massive CUDA / OpenCL parallelism)
Raw Hash ThroughputModerate (millions of hashes/sec)Massive (billions to tens of billions/sec)
Format Auto-DetectionYes (heuristics across hundreds of formats)No (requires explicit -m <mode>)
File Extraction UtilitiesYes (comprehensive 2john suite)No (relies on John or third-party extractors)
Complex & Salted FormatsExcellent for messy custom formats & single modeStrict format schemas per module
Best ForQuick checks, SSH keys, archives, CPU-only hostsLarge-scale audits, GPU rigs, massive wordlists
The standard pipeline: extract with John, crack with Hashcat
Use John's 2john utility to obtain the hash, then unleash Hashcat on GPU compute
$ zip2john secret.zip > zip.hash
$ hashcat -m 13600 -a 0 zip.hash rockyou.txt -r /usr/share/hashcat/rules/best64.rule
Interoperability: Hashcat natively recognizes output lines generated by zip2john (mode 13600), office2john (mode 9400–9600), and keepass2john (mode 13400).
When John's native OpenCL GPU support is enough
Run John's built-in OpenCL modules for fast ad-hoc checks without converting files
$ john --list=formats | grep -i opencl
$ john --format=sha512crypt-opencl --wordlist=rockyou.txt combined.txt
